현재: 별표3 신호 키워드 규칙 매칭. 정형화된 표현은 정확하나 복잡한 자유서술은 한계.
🤖 LLM 도입 시: 민원인이 신청서에 쓴 긴 자유서술(재해 경위)을 그대로 이해해 질병·신체부위·부담요인·노출기간을 한 번에 구조화. 키워드에 없는 표현도 문맥으로 파악.
② 판정서 본문 추출
현재: 본문에서 신체부위·부담요인·결정자료를 키워드로 추출. API가 본문 일부만 제공해 정확도 제한.
🤖 LLM 도입 시: 판정서 전문을 읽고 '인정/불인정을 가른 실제 판단 이유'까지 요약. 단순 빈도가 아니라 "왜 그렇게 판단했는가"의 패턴을 추출.
③ 사실관계 대조
현재: 직력·의료기록의 날짜·기간을 규칙으로 비교해 불일치·공백 점검.
🤖 LLM 도입 시: 진술서·의무기록의 서술형 내용까지 교차 분석해, 단순 날짜 불일치를 넘어 '진술과 기록의 맥락적 모순'까지 포착.
④ 판정위 보고서
현재: 1·2단계 결과를 템플릿으로 종합.
🤖 LLM 도입 시: 사건 맥락에 맞춘 자연스러운 서술형 검토의견 초안을 생성(담당자가 검수·수정).
⑤ 유사 판정서 추천 — 단계적 고도화 로드맵
1단계 현재 (키워드·규칙 매칭): 부위·부담요인·직종·노출기간 등 비교 요소의 일치 개수로 유사도를 산출. 투명하고 빠르나, '수부 저림'과 '손목 통증'처럼 표현이 다르면 놓칠 수 있음.
2단계 (임베딩 기반 의미 유사도) — 폐쇄망에서도 가능: 판정서 본문을 벡터로 변환해 '의미가 가까운' 사례를 검색. 동의어·표현 차이를 극복. 한국어 임베딩 모델은 로컬에서 실행되어 개인정보를 외부로 보내지 않으므로, LLM보다 먼저 도입할 수 있는 현실적 다음 단계.
3단계 (LLM 기반): 판정서 전문을 읽고 사실관계 구조·쟁점의 유사성까지 판단. 온프레미스 LLM 환경에서 가능.
왜 지금은 LLM을 쓰지 않는가 — 산재 자료는 민감한 개인정보이고 공단은 폐쇄망 환경이라, 외부 LLM API로 개인정보를 전송할 수 없습니다. 또한 판정 결과를 학습시키면 판정위 권한을 침범할 위험이 있습니다. 따라서 현재는 학습 없는 규칙기반 RAG로 구현했으며, 향후 공단 내부에 온프레미스(자체 서버) LLM이 도입되면 위 4개 지점에서 정확도와 활용성이 크게 향상될 수 있습니다. 핵심 원칙(AI는 판정하지 않는다)은 LLM 도입 후에도 동일하게 유지됩니다.

사용 안내

각 기능의 사용법과, 현재 데모로 동작하는 부분을 정리했습니다. 담당자·팀원이 먼저 읽어주세요.

⚠ 먼저 알아두세요 — 개인정보 주의
이 도구는 자료 검토를 보조할 뿐이며, 인정·불인정 판정은 하지 않습니다. 또한 ② 사실관계 타임라인에 실제 민원인의 직력·의료기록을 입력하면 그 정보가 (외부 배포 환경에서는) 서버로 전송될 수 있습니다. 테스트 시에는 실제 개인정보 대신 예시 데이터를 사용해 주세요. 실제 도입 시에는 공단 폐쇄망·온프레미스 환경을 전제로 합니다.
📌 적용 범위 — 요양급여신청 건
본 시스템의 대상 업무는 요양급여신청서에 대한 1차 재해조사입니다. 판정서 조회 시 본문에 유족급여·장해등급 등의 표지가 있는 건은 자동으로 제외하여, 요양급여 신청 건 중심으로 유사 사례를 제시합니다. (장해등급 결정은 판정위원회 심의 대상이 아니므로 원래 거의 포함되지 않으며, 유족급여 건은 본문 키워드로 걸러냅니다.)
① 유사 판정서 분석

무엇을 하나요? 민원인의 상병을 표준 질병분류로 변환하고, 같은 조건의 실제 판정서(공공데이터)를 찾아 인정/불인정 분포를 트리로 보여줍니다. 가장 유사한 판정서 3건과, 인정·불인정을 가른 핵심 자료를 데이터로 제시합니다.

사용법

  • A 일상어로 시작: 민원인 진술을 입력 → "분류어로 변환 · 사전 예측 기록" → 자문의사 소견을 붙여넣어 대조.
  • B 분류 선택으로 시작: 질병구분·직종을 직접 선택하고 신체부위·부담요인 필터 후 "판정서 트리 생성".
  • 트리의 판정서를 클릭하면 우측에 상세·가이드라인이, 본문 보기 버튼으로 원문 일부를 확인할 수 있습니다.
✅ 실제 데이터: 트리·유사사례·가이드라인은 근로복지공단 질병판정서 API에서 실시간 조회합니다(상단 초록 배너의 응답코드·조회건수가 증거). SERVICE_KEY 없이 실행하면 데모(샘플)로 동작합니다.
② 사실관계 타임라인

무엇을 하나요? 직력·의료기록을 한 시간축에 올려 직력 불일치·발병시점 재직지·노출기간 등 쟁점을 자동 점검합니다.

사용법

  • 판정서에서 실제 케이스 불러오기: 질병구분 선택 → 판정서 본문에서 직력이 추출된 실제 사건을 골라 타임라인 생성.
  • 직접 입력: 기본정보·직력·의료기록 행을 추가해 입력 후 "사실관계 분석".
  • 데모 예시: 26년 용접공(울산) 시나리오를 불러옵니다.
📌 데모/한계 안내: 개인의 4대보험 직력·의료기록 원본은 공공데이터에 없습니다(개인정보). 따라서 "판정서에서 불러오기"는 판정서 본문에 서술된 범위만 복원하며, 본문이 짧으면 일부만 추출됩니다. 실제 운영 시에는 담당자가 보유한 자료(엑셀 등)를 입력하는 방식이 됩니다.
③ 판정위 보고서

무엇을 하나요? ①②의 분석 결과를 상정용 보고서 한 장으로 종합하고, 인쇄/PDF로 저장합니다.

사용법: ①에서 트리 생성, ②에서 타임라인 분석을 먼저 한 뒤 ③에서 "보고서 생성" → "인쇄/PDF 저장".

📌 주의: ①②를 실행하지 않으면 보고서에 내용이 채워지지 않습니다. 두 단계를 먼저 진행해 주세요.
⚙ 시스템 구조

데이터 출처, 현재 처리 방식(규칙기반 RAG), 그리고 AI 모델 도입 시 강화되는 지점을 설명합니다. "왜 지금 LLM을 쓰지 않는가", "임베딩·LLM 고도화 로드맵"을 함께 담았습니다.

현재 데모로 동작하는 부분 요약
  • 실제 라이브: 질병판정서 조회, 유사사례 추천, 가이드라인 통계, 판정서 본문에서 케이스 추출 — 모두 공공데이터 기반(SERVICE_KEY 필요).
  • 데모/예시: 26년 용접공 타임라인 시나리오, 개인 의료기록 상세 — 개인정보 제약으로 예시 데이터 사용.
  • 발전 방향: 일상어·본문 이해, 의미기반 유사도(임베딩), 검토의견 초안 — 온프레미스 LLM/임베딩 도입 시 강화(시스템 구조 탭 참조).
